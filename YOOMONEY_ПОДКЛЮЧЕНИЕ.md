# Подключение приёма платежей ЮMoney — пошагово

Инструкция для этого проекта («ДЕЛО»). Описывает, что нажимать в кабинете
ЮMoney, что вписывать в переменные и как проверить, что всё сошлось.

Код уже готов: вебхук, подпись, сверка суммы, возврат пользователя после
оплаты. Осталось только настроить окружение и кабинет.

---

## Что понадобится

| Что | Где взять | Куда идёт |
|---|---|---|
| Номер кошелька | он у тебя есть | никуда — тянется из токена автоматически |
| `YOOMONEY_ACCESS_TOKEN` | OAuth, шаг 2 | окружение сервера |
| `YOOMONEY_CLIENT_ID` | кабинет, шаг 1 | окружение сервера |
| `YOOMONEY_NOTIFICATION_SECRET` | придумываешь сам, шаг 4 | окружение **и** кабинет |
| Домен сайта (HTTPS) | — | кабинет, шаг 5 |

Секрет вебхука — не то же самое, что токен. Токен даёт доступ к API, секрет
проверяет подпись уведомлений. Это две независимые строки.

---

## Шаг 1. Проверить приложение в кабинете ЮMoney

1. Открой https://yoomoney.ru/myservices/online
2. Найди своё приложение (то, для которого получен токен). Если его нет —
   создай: «Создать приложение».

Если приложение создаётся заново, оно запросит **Redirect URI**. Сейчас в коде
этот адрес нигде не используется (токен получается руками, OAuth-флоу в
приложении не реализован), поэтому значение нужно только для формальности.
Указывай что угодно правдоподобное:

```
https://твой-домен/payments/callback
```

Забери оттуда **Client ID** — это `YOOMONEY_CLIENT_ID`.

---

## Шаг 2. Получить токен

Токен даёт право читать историю операций и узнавать номер кошелька. Без него
`/payments/create` отвечает `400 «ЮMoney не настроен»`.

Два способа — выбери один.

### Способ А: быстрый, через «Документы» (рекомендую)

1. Открой https://yoomoney.ru/myservices/online/token
2. Отметь права: **`account-info`**, **`operation-history`**, **`payment-p2p`**
3. Нажми «Продолжить» → «Разрешить»
4. Скопируй выданный токен

Важно: у токена, выданного так, есть **срок действия**. Когда истечёт, оплата
перестанет создаваться, и в логах появится ошибка от ЮMoney. Для постоянной
работы лучше способ Б.

### Способ Б: через OAuth (постоянный токен)

1. Собери ссылку авторизации, подставив свой Client ID и Redirect URI:

```
https://yoomoney.ru/oauth/authorize?client_id=ТВОЙ_CLIENT_ID&response_type=code&redirect_uri=https://твой-домен/payments/callback&scope=account-info%20operation-history%20payment-p2p
```

2. Открой её в браузере, разреши доступ. Тебя перебросит на
   `redirect_uri?code=XXXXXX`
3. Скопируй `code` из адресной строки — он живёт минуты
4. Обменяй его на токен:

```bash
curl -X POST https://yoomoney.ru/oauth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "code=ВСТАВЬ_КОД" \
  -d "client_id=ТВОЙ_CLIENT_ID" \
  -d "grant_type=authorization_code" \
  -d "redirect_uri=https://твой-домен/payments/callback"
```

В ответе будет `access_token`. Это `YOOMONEY_ACCESS_TOKEN`.

Проверить, что токен живой:

```bash
curl -X POST https://yoomoney.ru/api/account-info \
  -H "Authorization: Bearer ВСТАВЬ_ТОКЕН"
```

Должен вернуться JSON с полем `account` — этот номер и есть твой кошелёк.

## Шаг 3. Придумать секрет вебхука

Это просто длинная случайная строка. Ничего регистрировать не нужно — ты её
придумываешь и потом вписываешь в двух местах (у себя и в кабинете ЮMoney).

Сгенерировать:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Получится что-то вроде:

```
K7gNq2xV9pLm4Rt8YwZb3Hj6Cd5FsA1e
```

Скопируй — это `YOOMONEY_NOTIFICATION_SECRET`.

## Шаг 4. Прописать переменные

### Локально

В корне проекта создай файл `.env` (он уже в `.gitignore` — в репозиторий не
попадёт). Основа — `.env.example`:

```bash
cd "C:/Users/armen/WorkBuddy AI/2026-09-18-11-44-56/delo-marketplace"
cp .env.example .env
```

Открой `.env` и заполни блок ЮMoney:

```ini
ENV=development
SECRET_KEY=любая-длинная-случайная-строка

# ЮMoney
YOOMONEY_ACCESS_TOKEN=токен_из_шага_2
YOOMONEY_CLIENT_ID=client_id_из_шага_1
YOOMONEY_REDIRECT_URI=https://твой-домен/payments/callback
YOOMONEY_NOTIFICATION_SECRET=секрет_из_шага_3

# Куда вернуть после оплаты. Для локальной разработки — адрес фронта.
FRONTEND_URL=http://localhost:3000
YOOMONEY_RETURN_PATH=/profile
```

Где лежит файл — важно. `load_dotenv()` ищет `.env` в **текущей рабочей
директории** процесса. `start.bat` делает `cd backend`, значит локально
надёжнее положить файл в `backend/.env` (или и туда, и в корень).

### На сервере (Render / VPS)

Те же пять переменных плюс `FRONTEND_URL` с боевым доменом:

```ini
YOOMONEY_ACCESS_TOKEN=...
YOOMONEY_CLIENT_ID=...
YOOMONEY_REDIRECT_URI=https://твой-домен/payments/callback
YOOMONEY_NOTIFICATION_SECRET=...
FRONTEND_URL=https://твой-домен
YOOMONEY_RETURN_PATH=/profile
```

Если деплой через `render.yaml` — переменные с `sync: false` задаются в
панели Render (Dashboard → сервис → Environment). Файл `.env` на сервер
не заливается.

Ключевое требование: **`YOOMONEY_NOTIFICATION_SECRET` должен совпадать**
в окружении сервера и в кабинете ЮMoney. Разошёлся — вебхук отвечает 403, и
это выглядит как атака, хотя на деле просто разные строки.

## Шаг 5. Включить уведомления в кабинете ЮMoney

Без этого шага зачисление возможно **только вручную** — кнопкой «Проверить
оплату». Вебхук и есть автоматическое зачисление.

1. Открой https://yoomoney.ru/myservices/online
2. Выбери своё приложение
3. Раздел **«Уведомления»** (HTTP-уведомления)
4. Включи их
5. **URL для уведомлений**:

```
https://твой-домен/payments/webhook/yoomoney
```

6. **Секрет для проверки подписи** — вставь значение из шага 3
   (то же, что в `YOOMONEY_NOTIFICATION_SECRET`)

Два жёстких требования ЮMoney:

- **Только HTTPS.** По HTTP уведомления не отправляются вообще.
- **Только публичный домен.** На `localhost` их не будет — их сервер физически
  не может достучаться. Для отладки локально нужен туннель (ngrok или аналог).

Тип уведомлений: нужен тот, который передаёт `label` — это **«Приход по
переводу»** / `card-incoming` для карточных и кошелёчных пополнений. Если
включить другой тип, вебхук не найдёт запись и ответит 404 «Unknown payment
label».

## Шаг 6. Проверить, что всё сошлось

### Проверка 1: токен подхватился

Запусти бэкенд и запроси статус:

```bash
curl http://localhost:8000/payments/status
```

Ожидаемый ответ:

```json
{"yookassa": {"configured": false}, "yoomoney": {"configured": true}}
```

Смотри именно на `yoomoney.configured`. Про `yookassa: false` не беспокойся —
этот провайдер в проекте не подключён, его переменные лежат
закомментированными.

Если `false` у `yoomoney` — токен не виден. Причина почти всегда в одном из двух:

- `.env` лежит не там, где ищет процесс (см. замечание про рабочую директорию
  в шаге 4);
- сервер не перезапущен. `yoomoney_client` создаётся **при импорте модуля**,
  то есть переменные читаются один раз на старте. Поменял `.env` — перезапусти
  бэкенд, иначе изменений не увидишь.

### Проверка 2: ссылка на оплату собирается

Войди в приложение, открой профиль → «Пополнить баланс», введи сумму.
Откроется страница ЮMoney. В адресной строке браузера проверь, что там есть:

```
receiver=41001...          ← твой номер кошелька
sum=1000                   ← сумма
label=delo_...             ← метка платежа
successURL=https%3A%2F%2F...%2Fprofile%3Fpayment%3Dreturn
```

Если `receiver` пустой — токен не дал номер кошелька (проверь права
`account-info`). Если нет `successURL` — не задан `FRONTEND_URL`.

### Проверка 3: вебхук доходит

Самый простой способ — реальный платёж на минимальную сумму (например, 10 ₽).
Порядок:

1. Оплати через открывшуюся форму
2. После оплаты тебя должно **автоматически вернуть** на страницу профиля
3. Баланс должен пополниться, появиться уведомление «Баланс пополнен»

Если вернуло, но не зачислило — вебхук не дошёл. Смотри логи бэкенда:

```bash
grep -i yoomoney backend/backend.log
```

Расшифровка типовых записей:

| Что в логе | Что значит |
|---|---|
| `Invalid ЮMoney webhook signature` | секрет не совпал с кабинетом |
| `webhook for unknown label=...` | тип уведомлений не тот, `label` не приходит |
| `YOOMONEY_NOTIFICATION_SECRET not set, cannot verify webhook` | переменная не задана на сервере |
| `amount mismatch ... crediting expected amount` | сумма в уведомлении разошлась; зачислена наша записанная — это защита, а не ошибка |
| ничего нет вообще | уведомления не включены или URL недоступен снаружи |

### Проверка 4: если вебхук пока не работает

Это не блокер. Ручная кнопка «Проверить оплату» в окне пополнения работает
всегда: она ходит в `operation-history` ЮMoney, находит платёж по `label` и
зачисляет. Так можно принимать деньги, пока разбираешься с вебхуком.

## Частые вопросы

**Нужен ли `YOOMONEY_REDIRECT_URI` в работе?**
Нет. В коде он не читается ни разу. Нужен только на этапе получения токена
через OAuth. Можно указать и забыть.

**Что если не задать `YOOMONEY_RETURN_PATH`?**
Возьмётся `/profile` по умолчанию. Если не задать и `FRONTEND_URL` —
`successURL` останется пустым, пользователь останется на сайте ЮMoney, и
зачисление будет ждать ручной кнопки. Ничего не сломается, просто вернётся
прежнее неудобство.

**Деньги могут зачислиться дважды?**
Нет. Вебхук идемпотентен по `credited_at`: повторная доставка уведомления
(ЮMoney повторяет при таймауте) видит, что платёж уже зачислен, и выходит.
Автовозврат и ручная кнопка используют один и тот же эндпоинт с той же защитой.

**Может ли кто-то подделать платёж?**
Нет. Подпись считается по секрету, которого у клиента нет. Плюс сумма берётся
из нашей записи, а не из уведомления, и `label` обязан существовать в базе —
иначе 404.

**Можно ли принимать на карту, а не в кошелёк?**
Форма уже настроена на карту: в ссылке `paymentType=AC`. Пользователь на
странице ЮMoney выберет способ сам.
