# 🛍️ Marketplace товаров - Варианты стратегии

## 📋 Общая концепция

Добавить в платформу ДЕЛО раздел продажи физических товаров (новых и б/у) с разными категориями.

---

## 🎯 Варианты стратегии

### Вариант 1: "Объявления" (как Avito/OLX)

**Суть**: Простые объявления о продаже товаров

**Как работает:**
- Продавец создаёт объявление (фото, описание, цена)
- Покупатель видит объявления, связывается с продавцом
- Сделка происходит напрямую (встреча, доставка)
- Платформа НЕ участвует в оплате

**✅ Плюсы:**
- Просто и быстро реализовать
- Не нужна логистика
- Минимум ответственности платформы
- Продавцы могут продавать без комиссии

**❌ Минусы:**
- Нет гарантий безопасности сделки
- Больше мошенничества
- Меньше доверия
- Платформа не зарабатывает на транзакциях

**💰 Монетизация:**
- Платное продвижение объявлений
- PRO аккаунты с большим лимитом объявлений
- Реклама

---

### Вариант 2: "Маркетплейс с эскроу" (как OZON/Wildberries) ⭐ РЕКОМЕНДУЕТСЯ

**Суть**: Безопасные сделки через платформу с эскроу

**Как работает:**
1. Продавец создаёт товар (фото, описание, цена, наличие)
2. Покупатель оформляет заказ
3. Деньги замораживаются в эскроу
4. Продавец отправляет товар (или передаёт лично)
5. Покупатель получает и подтверждает
6. Деньги переводятся продавцу (минус комиссия)
7. Если проблема → диспут → арбитраж

**✅ Плюсы:**
- Безопасность для обеих сторон
- Защита от мошенничества
- Доверие к платформе
- Платформа зарабатывает комиссию
- Контроль качества
- Интегрируется с существующей системой (эскроу уже есть!)

**❌ Минусы:**
- Сложнее реализовать
- Нужна логистика (или интеграция с доставкой)
- Больше ответственности

**💰 Монетизация:**
- Комиссия с продаж (5-15%)
- Продвижение товаров
- PRO аккаунты для продавцов

---

### Вариант 3: "Гибридная модель" (Avito + безопасная сделка)

**Суть**: Объявления + опциональная безопасная сделка через эскроу

**Как работает:**
- Продавец создаёт объявление
- Покупатель может:
  - **Вариант А**: Связаться напрямую (бесплатно)
  - **Вариант Б**: Купить через платформу с эскроу (комиссия)
- Выбор остаётся за пользователями

**✅ Плюсы:**
- Гибкость для пользователей
- Привлекает больше продавцов (есть бесплатный вариант)
- Монетизация на желающих безопасность
- Постепенный переход к эскроу

**❌ Минусы:**
- Сложная логика
- Два разных потока сделок
- Может быть путаница для пользователей

## 🎯 Моя рекомендация: Вариант 2 (Маркетплейс с эскроу)

### Почему?

1. **У вас уже есть эскроу-система** - используем существующий код!
2. **Логичное расширение** - задачи → товары (та же логика)
3. **Безопасность = доверие** - главное конкурентное преимущество
4. **Больше прибыли** - комиссия с каждой продажи
5. **Уникальность** - большинство досок объявлений НЕ имеют эскроу

### Как будет работать:

```
📦 Товар (Product) = Задача (Task) + дополнительные поля

Общее с задачами:
- Заказчик → Покупатель
- Исполнитель → Продавец  
- Бюджет → Цена
- Эскроу → Эскроу
- Статусы (open, in_progress, completed, disputed)
- Отзывы и рейтинги
- Чаты
- Арбитраж споров

Новое для товаров:
- Состояние (новый/б/у)
- Количество (stock)
- Галерея фото (несколько фото)
- Характеристики товара
- Доставка (самовывоз/доставка/оба)
- Адрес продавца
- Габариты и вес (для доставки)
```

## 📦 Функционал (Вариант 2)

### Для продавца:

1. **Создание товара**:
   - Название, описание
   - Категория (электроника, одежда, мебель, и т.д.)
   - Состояние (новый/б/у)
   - Цена
   - Количество на складе
   - Фото (до 10 фото)
   - Характеристики
   - Варианты доставки
   - Адрес (для самовывоза)

2. **Управление товарами**:
   - Список моих товаров
   - Редактирование
   - Снять с продажи
   - Управление остатками

3. **Заказы**:
   - Входящие заказы
   - Подтвердить заказ
   - Отметить как отправленный
   - Указать трек-номер

### Для покупателя:

1. **Просмотр**:
   - Каталог товаров
   - Фильтры (категория, цена, состояние, город)
   - Поиск
   - Карточка товара (фото, описание, продавец)

2. **Покупка**:
   - Добавить в корзину
   - Оформить заказ
   - Выбрать доставку/самовывоз
   - Оплата (деньги в эскроу)

3. **Мои покупки**:
   - История заказов
   - Отследить доставку
   - Подтвердить получение
   - Оставить отзыв
   - Открыть диспут

### Система:

1. **Эскроу**:
   - Деньги замораживаются при заказе
   - Продавец получает после подтверждения
   - Комиссия платформы: 7-10%

2. **Доставка**:
   - Самовывоз (указать адрес)
   - Доставка (интеграция с СДЭК/Почта России)
   - Продавец указывает трек-номер

3. **Диспуты**:
   - Покупатель может открыть спор
   - Администратор разбирает
   - Возврат средств или передача продавцу

## 🗂️ Структура базы данных (новые таблицы)

```sql
-- Товары
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    seller_id INTEGER REFERENCES users(id),
    title VARCHAR(200) NOT NULL,
    description TEXT,
    category VARCHAR(50),
    condition VARCHAR(20), -- 'new' или 'used'
    price INTEGER NOT NULL,
    stock INTEGER DEFAULT 1,
    images TEXT[], -- массив URL фотографий
    specifications JSONB, -- характеристики товара
    delivery_options VARCHAR(50), -- 'pickup', 'delivery', 'both'
    address TEXT, -- адрес продавца для самовывоза
    status VARCHAR(20) DEFAULT 'active', -- active, sold, removed
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Заказы товаров
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    product_id INTEGER REFERENCES products(id),
    buyer_id INTEGER REFERENCES users(id),
    seller_id INTEGER REFERENCES users(id),
    quantity INTEGER DEFAULT 1,
    total_price INTEGER NOT NULL,
    delivery_method VARCHAR(20), -- 'pickup' или 'delivery'
    delivery_address TEXT,
    status VARCHAR(20) DEFAULT 'pending', -- pending, confirmed, shipped, delivered, completed, disputed, cancelled
    tracking_number VARCHAR(100),
    escrow_amount INTEGER, -- замороженная сумма
    platform_fee INTEGER, -- комиссия платформы
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Категории товаров
CREATE TABLE product_categories (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    slug VARCHAR(100) UNIQUE,
    icon VARCHAR(50),
    parent_id INTEGER REFERENCES product_categories(id)
);
```
