# Аудит безопасности — ноябрь 2026

Ветка `security/audit-fixes`. Все наборы CI (серверные, самодостаточные,
login-throttle, vitest) прогнаны локально на Postgres 16 + Redis — зелёные.
Новый регресс-набор: `tests/security/check_audit_fixes.py` (44 проверки), добавлен в CI.

## Что исправлено

### Деньги и гонки
- `/payments/confirm`: rate-limit, провайдер берётся из записи платежа, зачисление
  через атомарный claim `credited_at` — параллельные подтверждения зачисляют один раз.
- Вебхук ЮMoney: игнорирует `codepro`, `unaccepted`, валюту ≠ 643; атомарный claim.
- `assign_task`: запрет назначить самого себя; перевод open→in_progress атомарно до списания.
- `complete_task`, отмена, споры, решения арбитража, переходы заказов товаров —
  через атомарные UPDATE … WHERE status=… (при гонке — 409/400, без двойных выплат/возвратов).
- Эскроу заказа товара записывается отрицательной суммой (как у услуг).
- Отклики: нельзя откликаться на свой/закрытый заказ и дважды; атомарное списание кредитов.

### Изменения поведения (важно для фронтенда/пользователей)
- **Заказчик больше не может отменить заказ в работе** и забрать эскроу в одностороннем
  порядке — только через спор. Отказаться от заказа в работе может исполнитель
  (эскроу возвращается заказчику).
- Спор отзывает только инициатор: заказчик → заказ возвращается в работу (без возврата),
  исполнитель → отказ + возврат эскроу заказчику.
- Ссылки на файлы: формат `f2` с TTL (`FILE_TOKEN_TTL_SEC`, по умолчанию 6 ч).
  Старые ссылки `f1` недействительны, пока не задан `FILE_TOKEN_ALLOW_LEGACY=1`.
- `specialist_email` в откликах всегда пустой; чужие отклики видит только автор заказа.
- Публичные имена продавцов/авторов отзывов больше не подставляют e-mail.
- В production: Swagger/ReDoc выключены (включить — `ENABLE_API_DOCS=1`);
  SQLite запрещён (`ALLOW_SQLITE_IN_PRODUCTION=1` — осознанный обход).

### Аутентификация
- `decode_token` принимает только access-токены (refresh больше не работает как access).
- Логин с неизвестным e-mail тоже считает bcrypt (нет тайминг-перебора адресов).
- Токены сброса пароля хранятся как SHA-256, одноразовость атомарна; после сброса
  отзываются все refresh-токены и прочие токены сброса.
- Верификация: решение модератора только из `pending`.

### Инфраструктура
- `client_ip`: `X-Forwarded-For`/`X-Real-IP` учитываются только от приватных адресов (прокси).
- nginx: `client_max_body_size 10m`, `real_ip` только из приватных сетей,
  `X-Forwarded-For $remote_addr` (клиент не может подложить свою цепочку).
  **Нужно пересобрать образ frontend.**
- SPA fallback: защита от path traversal (`resolve()` + `is_relative_to`).
- Sentry: `send_default_pii=False`; `/health/db` не отдаёт текст ошибки;
  URL с паролями (Redis/брокер) маскируются в логах.
- Dev-compose: Postgres/Redis слушают только `127.0.0.1` (раньше — все интерфейсы
  с дефолтным паролем).
- Telegram-бот: берёт открытые заказы с пагинацией, не рассылает адрес.
- Документация ЮMoney: убран лишний scope `payment-p2p`.

## Что не сделано (рекомендации)
- Отдельный ключ шифрования данных вместо `SECRET_KEY`; ротация refresh-токенов.
- Выплаты: 2FA и принцип «двух ключей» (maker-checker) для админа.
- Маскирование персональных данных в админке; скрытие точного адреса до назначения.
- Политика комиссии/`withdraw_amount`, резервные копии БД (на Render `plan: free`
  Postgres удаляется через 30 дней).
- В `render.yaml` у backend/worker/beat генерируются **разные** `SECRET_KEY`
  (`generateValue` на каждый сервис) — лучше задать один общий вручную.
- `alembic upgrade head` в CMD Docker-образа; gitleaks в CI.
- WebSocket-чат при нескольких воркерах (нужен Redis pub/sub).
- Токен в `localStorage` (XSS → кража сессии) — перейти на httpOnly-cookie.
- Ограничение длины промпта в AI-эндпоинтах; `noopener` у `window.open`.

> `docker-compose.infra.yml` и `docker-compose.yml`: пароль Postgres больше не хранится
> в репозитории (ни захардкоженный, ни дефолтный `marketplace_secret`) — без
> `POSTGRES_PASSWORD` в `.env` compose не стартует. Старый пароль остался в истории git —
> если база где-то запущена с ним, смените его.
