# Telegram-бот ДЕЛО

Бот делает две вещи:

- **🎯 Радар заказов.** Новое задание приходит в Telegram сразу после
  публикации. Фильтры — кнопками: категории, минимальный бюджет, город
  (удалённые задания приходят при любом городе). Регистрация на сайте для
  этого не нужна. На странице «Задания» есть кнопка «Заказы в Telegram».
- **🔔 Личные уведомления.** Отклики, выбор исполнителя, сообщения в чате
  сделки, оплата, споры, заказы товаров — всё, что появляется в колокольчике
  на сайте. Нужно привязать аккаунт: «Профиль → Настройки → Подключить
  Telegram».

Ещё у бота есть кнопка меню «ДЕЛО»: она открывает сайт прямо внутри
Telegram (Mini App). Команда `/stop` удаляет из базы всё, что касается этого
чата.

## Как устроено

| Что | Где |
| --- | --- |
| Процесс бота | `python -m app.telegram.bot`, сервис `bot` в `docker-compose.prod.yml` (образ backend) |
| Код | `backend/app/telegram/`: `client.py` — Bot API, `core.py` — данные и тексты, `bot.py` — сообщения и рассылка |
| Данные | таблицы `telegram_chats`, `telegram_link_tokens`, `telegram_deliveries` — в общей базе и в резервных копиях |
| API для сайта | `backend/app/api/telegram.py`: `/telegram/info`, `/telegram/status`, `/telegram/link` |
| Тест | `tests/security/check_telegram_bot.py` (идёт в CI) |

Уведомления бот берёт из таблицы `notifications`, поэтому всё новое, что
сайт кладёт в колокольчик, само приходит и в Telegram — код сайта для этого
трогать не нужно. Каждые 3 секунды бот смотрит, что появилось, и отмечает
отправленное, поэтому после перезапуска ничего не теряется и не дублируется.
Что пропущено, пока бот был выключен, приходит, если ему не больше 2 часов.

Что бот не отправляет намеренно:

- точный адрес задания — в радаре только город, как в ленте сайта;
- чужой email — вместо него маска `i***@mail.ru`;
- сообщения чата, пока человек сам сидит на сайте;
- то, что накопилось до привязки или пока уведомления были выключены.

Ссылка привязки одноразовая и действует 15 минут. В базе хранится только её
хэш.

## Подключение

**1. Создайте бота.** В Telegram откройте @BotFather → `/newbot`. Придумайте
имя, например «ДЕЛО — заказы», и адрес, который оканчивается на `bot`, например
`delo_zakazy_bot`. BotFather пришлёт токен вида `123456789:AA...`.

> Токен — это пароль от бота. Не присылайте его в чаты и не показывайте на
> скриншотах. Если он утёк, отправьте в @BotFather `/revoke` и замените токен
> в `.env`.

Можно оставить и прежнего бота: тогда возьмите в @BotFather его токен
(`/mybots` → бот → API Token). Старые подписки радара хранились в файле и
не переносятся, поэтому подписчикам нужно один раз нажать `/start`.

**2. Впишите токен на сервере.**

```bash
cd /opt/delo-marketplace
nano .env          # строка TELEGRAM_BOT_TOKEN=123456789:AA...
```

**3. Обновите сайт** — как обычно:

```bash
bash scripts/vps_update.sh
```

Скрипт соберёт образы, создаст таблицы бота и перезапустит сервисы. Если вы
меняете только токен, без обновления кода, хватит одной команды:

```bash
docker compose -f docker-compose.prod.yml up -d backend bot
```

**4. Проверьте.**

```bash
docker compose -f docker-compose.prod.yml logs --tail 20 bot
```

В журнале должна быть строка `telegram: бот @имя_бота запущен`. Дальше
напишите боту `/start`, а на сайте проверьте кнопку «Заказы в Telegram» на
странице «Задания» и панель Telegram в «Профиль → Настройки».

Команды, описание и кнопку меню бот настраивает сам при запуске. В @BotFather
можно поставить аватарку: `/setuserpic`.

## Если что-то не так

| В журнале или на сайте | Причина | Что делать |
| --- | --- | --- |
| `409 Conflict` | с этим токеном работает ещё одна копия бота: старый сервис на Render, запуск с домашнего компьютера | остановите её или выпустите новый токен (`/revoke`) |
| `Telegram не принял токен (401)` | в `.env` неверный токен | проверьте строку `TELEGRAM_BOT_TOKEN` |
| `TELEGRAM_BOT_TOKEN не задан` | токена нет | шаг 2 |
| на сайте нет кнопок Telegram | backend не видит токен | `docker compose -f docker-compose.prod.yml up -d backend` |
| в веб-версии Telegram вместо сайта «не позволяет установить соединение» | сайт запрещает встраивать себя во фрейм | разрешено только `web.telegram.org` — строка `frame-ancestors` в `frontend/nginx-security-headers.conf` |
| контейнер `bot` в статусе unhealthy | завис один из потоков бота | `docker compose -f docker-compose.prod.yml restart bot`, затем журнал |

Мониторинг (`scripts/monitor.sh`) может слать оповещения через этого же бота —
они не мешают друг другу: мониторинг только отправляет сообщения.

## Переменные

| Переменная | Нужна | Зачем |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | да | токен бота; читают и бот, и backend |
| `FRONTEND_URL` | да | адрес сайта для кнопок; кириллический домен переводится в punycode сам |
| `TELEGRAM_BOT_USERNAME` | нет | имя бота без `@`, если с сервера не работает `getMe` |
| `TELEGRAM_API_URL` | нет | свой адрес Bot API (прокси); по умолчанию `https://api.telegram.org` |
| `TELEGRAM_DELIVERY_INTERVAL` | нет | пауза между проходами рассылки, секунд (по умолчанию 3) |
